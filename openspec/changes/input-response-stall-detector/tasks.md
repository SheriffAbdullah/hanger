Deviations from the design

- Merge gap: samples merge when their start-to-start gap is within the merge gap plus 100 ms (timer jitter), because a timed-out request occupies the whole 1000 ms; the spec's 10.0/10.3/10.6/12.5 s example still gives 3 samples plus a blip.
- The helper writes `active` input-recent spans inside the 10 s `input-window` records (compacted into `inputStall.evaluable.activeSpans`) so the idle/evaluated join for probe agreement can be recomputed from the report alone; this adds no per-tick record.
- The helper is started before the counter session (so the session can meter it), that is before the `run-start` record; `recover` finds it by record type.
- Agreement and corroboration values under `diagnosis` are plain `{num, den, value}` as in the design example, not provenance records; all `inputStall` numbers are provenance records.
- The calm baseline p95 is an n-weighted estimate from the 10 s window p95 values (the helper keeps no per-measurement list).
- The scope classifier is `classifyForeground` (the resolver's own `classifyName` is unchanged); `resolver.matchData()` supplies the serializable match data.
